# 同声传译简洁界面 技术方案

## 需求概述

> **项目名称**：声桥轻量版（LinguaBridge Lite）
>
> **目标**：将现有“声桥”客户端重构为轻量级同传工具，保留核心功能，简化界面，增强历史整合与多端支持。
>
> **核心原则**：
>
> - 
>
>   ✅ 速度只快不慢（优于或等于原版）
>
> - 
>
>   ✅ 中英互译功能必须保留
>
> - 
>
>   ✅ 支持原客户端所有音频源（系统音频、麦克风等）
>
> - 
>
>   ✅ 历史翻译需整合、可回溯、不丢失
>
> - 
>
>   ❌ 删除冗余UI（如左侧菜单、诊断、设置、重试按钮等）
>
> - 
>
>   ❌ 不再显示“已定稿”“队列拥塞”等技术标签

------

## 一、核心功能需求

### 1.1 同声传译核心能力（不可删减）

| 功能项     | 要求                                                         |
| ---------- | ------------------------------------------------------------ |
| 翻译方向   | 支持 `中文 → 英文`、`英文 → 中文` 两种模式，可切换           |
| 翻译速度   | ≥ 原版（1013ms），理想目标 ≤ 800ms（如有优化空间）           |
| 音频源支持 | 保留原客户端所有音频源：系统音频、麦克风、文件等（按需列出） |
| 实时显示   | 原文 + 译文同步显示，译文需加粗/高亮，便于快速阅读           |
| 暂停/继续  | 保留“停止同传”按钮（可更名为“暂停”），支持随时恢复           |

> ✅ **注意**：翻译延迟必须控制在可接受范围内（<1s），避免影响使用体验。

------

### 1.2 历史记录整合（核心痛点解决）

> ❗当前问题：历史记录“一句句散开”，无法整合上下文，用户找不到之前翻译的内容。

#### ✅ 重构方案：

- 

  **历史记录模块**：

  - 

    位于主界面下方或侧边（可折叠），默认收起，点击展开。

  - 

    每条记录包含：

    - 

      时间戳（如 `00:15.750`）

    - 

      原文（英文/中文）

    - 

      译文（对应语言）

    - 

      状态标记（可选：`已修订` / `自动翻译`）

  - 

    支持**按时间倒序排列**，最新在上。

  - 

    支持**一键复制整段历史**（或导出为文本）。

  - 

    支持**搜索关键词**（可选，增强可用性）。

- 

  **上下文整合**：

  - 

    当前翻译行上方显示“最近3条历史记录”（可配置），帮助用户理解语境。

  - 

    支持“合并连续语句”功能（如连续两句英文→中文，可自动合并为一段）。

------

## 二、界面设计（极简工具风）

> ✅ 目标：像“悬浮窗”或“小工具”，不占屏幕，不打扰用户。

### 2.1 主界面布局（建议）

```
┌──────────────────────────────────────────────┐
│  [语言方向：英文→中文 ▼]  [暂停]  [设置⚙️] │
├──────────────────────────────────────────────┤
│                                              │
│   But Jonathan insisted on paying, so he…    │
│   **但乔纳森坚持要付款…**                    │
│                                              │
└──────────────────────────────────────────────┘
        ↓ 下方可折叠历史面板（默认收起）
```

- 

  **顶部控制栏**：

  - 

    语言方向下拉框（中英互译）

  - 

    “暂停”按钮（原“停止同传”）

  - 

    “设置”图标（仅保留必要选项：音频源、字体大小、主题）

- 

  **主显示区**：

  - 

    原文（灰色/小字号）

  - 

    译文（加粗/大字号/深色，突出显示）

  - 

    无“已定稿”“ms延迟”等技术标签

- 

  **历史面板**（可折叠）：

  - 

    显示最近10条翻译记录（可滚动）

  - 

    每条带时间戳 + 原文 + 译文 + 状态

  - 

    支持“清空历史”、“导出为TXT”

## 四、技术约束 & 优化建议

### 4.1 性能要求

- 

  翻译延迟 ≤ 1000ms（理想 ≤ 800ms）

- 

  内存占用 ≤ 200MB（轻量级工具）

- 

  启动时间 ≤ 3s

### 4.2 重构建议

- 

  使用轻量级框架（如 Tauri / Electron + React/Vue 精简版）

- 

  移除不必要的模块（诊断、重试、队列拥塞提示）

- 

  历史记录使用本地存储（IndexedDB / localStorage），无需后端

- 

  支持快捷键（如 Ctrl+Space 暂停，Ctrl+H 查看历史）

## 最终方案

### 聚焦轻量版界面结构
移除左侧导航、诊断、重试、延迟、队列、技术状态和底部 transport bar，将现有功能重新组合为一个紧凑主窗口。

选择理由：当前 App.tsx 已经具备全部行为入口，主要问题集中在信息架构和视觉密度。保留事件处理函数并替换 JSX/CSS，可以控制风险并满足极简工具目标。

### Windows 优先的多端边界
跨平台共享 UI、历史和应用行为，系统音频按现有能力分级验收，并在产品说明中明确平台限制。

选择理由：当前仓库只有 Windows WASAPI helper 能力检测，macOS/Linux 没有等价原生采集实现。将原生补齐纳入本次会显著扩大范围并偏离轻量界面核心目标。

### 持久化分组历史（仅按 8 秒间隔分段）
将实时字幕状态和长期历史状态解耦，使用版本化 localStorage 保存精简记录；连续内容只按 8 秒间隔分段，并提供折叠浏览、复制、TXT 导出和确认后清空。

选择理由：用户需要完整连续段落，固定句数会人为切断语义。来源、语言方向和会话变化仍然形成自然边界，8 秒静默作为同一会话中的时间边界。

### 实时速度零回退验收门槛
实时处理链路保持原样，历史加载、分组、裁剪和存储全部移出首稿可见路径；改造前后使用固定样本做成对对比，任何可归因于本次改造的延迟增加都会阻断验收。

选择理由：现有 qwen-turbo fast-draft 已有 mean 293.5ms、P95 362ms 的 provider 基准。界面改造的主要性能风险来自 renderer 同步计算和 localStorage 写入，因此需要从代码路径和测量门槛两侧约束。

## 接口与数据调整

- preload 新增 exportSubtitleHistory(content, suggestedName) IPC，仅写入用户在保存对话框确认的 TXT 文件。

## 联调边界

- 不新增诊断、重试、队列或延迟可视化入口。
- 不修改 ASR、翻译、润色和 provider 调度算法。
- 搜索、快捷键和 Web 版不进入本次 MVP。
- 不修改 ASR、翻译 prompt、模型、partial 门槛、debounce、active/backfill 调度和轮询参数。
- 性能回归未关闭前不得判定需求验收通过。

## 风险与注意事项

- App.tsx 仍是大型组件，布局替换需要逐段迁移事件绑定，避免误删采集与 provider 行为。
- 暗色主题需要同时检查错误态和悬浮字幕对比度。
- 不同 macOS/Linux 版本、权限和窗口管理器会影响 desktopCapturer 的系统音轨可用性，文档需保持明确。
- 不限制句数可能形成长段落，历史面板通过自动换行、内部滚动和完整导出承载。
- localStorage 存在容量和写入失败风险，通过精简字段、500 条上限、异常回退及可导出降低影响。
- 延迟写入需要在窗口关闭前冲刷，避免最后一帧字幕丢失。
- 英文与中文段落连接规则需要单元测试覆盖标点和空格。
- 真实 provider 和公网延迟具有波动，采用相同环境、交替顺序、至少 3 轮和中位数对比降低噪声。
- 长段落展开会增加 DOM 文本量，历史默认收起并使用列表窗口内滚动，必要时仅渲染最近可见分组。
- beforeunload 同步冲刷只发生在窗口关闭路径，不进入实时字幕路径。
