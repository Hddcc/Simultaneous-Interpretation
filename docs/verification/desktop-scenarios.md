# 桌面场景验证清单

本文档用于记录声桥 LinguaBridge 在真实桌面使用场景下的验证方法。浏览器视频、会议软件和通话软件都需要在 Windows 桌面环境中手工执行；自动化测试负责检查场景清单是否完整、是否包含预期信号、证据记录和 fallback 路径。

## 验证前准备

- 已安装依赖并可运行 `npm.cmd run build`。
- 已按 `.env.example` 配置所需 provider；使用真实 OpenAI ASR 时配置 `OPENAI_API_KEY`。
- 测试系统音频时，先在客户端选择“系统音频”，刷新桌面/窗口来源。
- 测试麦克风 fallback 时，确认系统允许 Electron 访问麦克风。
- 测试悬浮字幕时，先在客户端设置中点击“打开悬浮字幕”。

## 浏览器视频系统音频同传

**目标**：验证浏览器正在播放的英语或中文视频能通过系统音频产生双语字幕。

**步骤**

1. 在浏览器中打开一段包含清晰演讲的视频。
2. 在应用中选择“系统音频”，选择浏览器或桌面来源。
3. 点击“开始”，保持视频播放 30 秒以上。
4. 观察当前句字幕、音量条、音频块数量、ASR 延迟、翻译延迟和字幕历史。

**通过标准**

- 音量条随浏览器声音变化。
- 音频块数量持续增加。
- Payload 显示 provider-ready 或客户端明确显示当前捕获限制。
- 出现原文和译文字幕，过程不需要上传音视频文件。
- 主字幕区只突出当前句，上一句弱化显示或进入历史。

**记录证据**

- 浏览器名称、视频语言和视频时长。
- 是否出现双语字幕。
- 是否使用 fallback。
- 主客户端状态栏、当前句字幕和字幕历史截图。

## Edge/B站追帧与 50 样本报告

**目标**：验证真实系统音频下的 fast-draft、端到端分位数、主字幕无回退、历史补全和压力恢复。

**步骤**

1. 在 Edge 打开固定英语 B站视频，记录链接、时长、语速片段和系统输出设备。
2. 记录 `REALTIME_ASR_PROVIDER/MODEL`、`TRANSLATION_PROVIDER/MODEL`、`FAST_DRAFT_MODEL`、地域和网络环境，隐藏 API Key。
3. 启动系统音频同传，先丢弃 5 个 warm-up 首稿，再连续采集至少 50 个 provider-backed、非 fallback 首稿。
4. 播放快速连续语句，记录 active lag、superseded partial、cancellation、late final backfill 和 rollback block。
5. 制造短暂压力后恢复网络或正常语速，记录 refinement 暂停/恢复与 catch-up 恢复时间。
6. 保存 `window.__realtimeDiagnostics` 和 `window.__realtimeReferenceReport`，或把同样的原始样本交给 `npm run verify:latency-reference -- <json>`。

**通过标准**

- fast-draft mean `<=500ms`、P95 `<=900ms`；end-to-end P50 `<=800ms`、P95 `<=1500ms`。
- 至少 50 个预热后合格首稿，errors、fallbacks 和 missing timestamps 分开报告。
- active lag `<=1 cue`，压力解除后 `<=2s` 回到 healthy。
- 晚到 partial 不覆盖当前句；晚到 final 和 final 译文更新历史；润色不改变首稿样本。
- 客户端标签、按钮、面板、徽标、设置项和悬浮字幕控制保持原样。

**必要证据**

- provider/model、网络、预热数、请求数、样本数和固定视频信息。
- fast-draft/end-to-end 的 count、mean、P50、P95、max，以及 errors/fallbacks/missing。
- 最大 active lag、压力清除时刻、healthy 恢复时刻、取消与历史补全计数。
- 当前句无回退、历史晚到补全、refinement 暂停/恢复和控件未变化的截图或录屏。

## 会议软件系统音频同传

**目标**：验证 Tencent Meeting 或同类会议软件音频可以被捕获，或记录清晰的平台限制和 fallback。

**步骤**

1. 打开 Tencent Meeting 或同类会议软件。
2. 加入测试会议或播放会议录制，确保会议软件正在输出语音。
3. 在应用中选择“系统音频”，点击“开始”。
4. 打开悬浮字幕，并切换焦点到会议窗口。

**通过标准**

- 捕获成功时，字幕历史出现会议语音的原文和译文。
- 悬浮字幕在会议窗口上方保持可读。
- 捕获受限时，客户端显示可恢复错误，保留停止、重试和切换备用输入操作。
- 悬浮字幕跟随当前句原地更新，不显示 provider 调试信息。

**可接受 fallback**

会议软件阻止系统音频捕获时，切换“麦克风”收外放会议声音；记录为平台限制和 fallback 成功。

## 通话软件系统音频同传

**目标**：验证 WeChat 或同类通话软件音频可以被捕获，或记录清晰的平台限制和 fallback。

**步骤**

1. 打开 WeChat 或同类通话软件。
2. 准备一段通话音频或实际测试通话。
3. 在应用中选择“系统音频”，点击“开始”。
4. 观察主客户端和悬浮字幕的字幕更新情况。

**通过标准**

- 捕获成功时，字幕来源来自系统音频。
- 捕获受限时，显示可恢复错误和 fallback 操作。
- 切换麦克风 fallback 后，音量、ASR 和翻译事件继续更新。
- fallback 后仍使用歌词式当前句字幕。

## 歌词式低延迟字幕与修订

**目标**：验证主字幕区围绕当前句更新，stable partial 可先生成草稿译文，final 或翻译修正到达后同一句字幕原地更新。

**步骤**

1. 准备一段包含短句、长句和自然停顿的中英测试音频。
2. 选择文件模拟或系统音频并开始同传。
3. 观察 stable partial 出现时是否先显示草稿译文。
4. 等待 final 或翻译修正返回，确认同一句字幕原地更新。
5. 展开字幕历史，确认当前句结束后进入整合段落，修订内容覆盖原记录。

**通过标准**

- 主字幕区只突出一个 active cue。
- 译文作为主要阅读内容，源文作为辅助上下文。
- 上一句弱化显示或进入历史，主区域不会累加成长段落。
- 过期翻译结果不会覆盖更新版本。
- 悬浮字幕与主窗口显示同一个 active cue，并在修订时原地更新。

**记录证据**

- stable partial 到首个译文可见的大致延迟。
- 修订前后同一句字幕的截图。
- 当前字幕与整合历史的截图。

**记录证据**

- 通话软件名称、音频设备和测试语种。
- 系统音频是否成功。
- fallback 是否成功。
- 恢复提示或 fallback 后字幕状态截图。

## 麦克风备用输入

**目标**：验证系统音频受限时，麦克风仍可作为备用输入完成同传。

**步骤**

1. 在应用中选择“麦克风”。
2. 播放外放语音或直接朗读。
3. 点击“开始”，观察当前字幕和折叠历史的更新。

**通过标准**

- 当前原文和译文随外部声音更新。
- 字幕历史出现双语片段。
- provider 不可用时仍保留源文和错误提示。

## 悬浮字幕覆盖其他应用

**目标**：验证用户切换到浏览器、会议、播放器或通话窗口时，悬浮字幕仍然可读。

**步骤**

1. 开启任意实时输入来源。
2. 点击“打开悬浮字幕”。
3. 切换焦点到其他应用窗口。
4. 观察悬浮字幕是否保持置顶和可读。

**通过标准**

- 悬浮字幕保留最新译文、源文和可选上一句上下文。
- 悬浮字幕可拖动到目标位置，常规字幕显示不出现滚动条。
- 受限、重连或异常时显示紧凑状态。
- 字幕文本和状态信息不重叠。
- active cue 修订时，悬浮窗原地更新。

## 悬浮歌词锁定与鼠标穿透

**目标**：验证悬浮歌词窗可拖动、可锁定，并且锁定后可继续操作下方浏览器、会议或播放器窗口。

**步骤**

1. 开启任意实时输入来源并打开悬浮字幕。
2. 将悬浮字幕拖到浏览器、会议或播放器窗口上方。
3. 悬停字幕窗口，点击“锁定”。
4. 在字幕窗口覆盖区域下方点击网页、会议控件或播放器控件。
5. 回到主客户端，点击“解锁悬浮字幕”或“重置悬浮位置”。

**通过标准**

- 未锁定时，悬浮字幕可自由拖动。
- 锁定后，控制按钮隐藏或弱化，字幕仍保持可读。
- 支持鼠标穿透的平台上，下方应用可以被正常点击。
- 主客户端可以解锁、关闭或重置悬浮字幕。

## 双语润色对比

**目标**：验证 fast translation 先显示，大模型润色随后原地修订，减少翻译腔。

**步骤**

1. 准备包含自然口语和技术名词的英文或中文音频。
2. 开始同传，观察首个译文是否快速出现。
3. 等待 final 或稳定 cue 后，观察当前句或最近历史是否被润色修订。
4. 展开字幕历史，确认润色内容原地覆盖对应记录；性能指标通过自动化报告记录。

**通过标准**

- 快速译文先出现，润色不阻塞首屏字幕。
- 润色结果原地替换当前 cue 或 revision window 内的最近历史。
- 中文更自然，英文更适合作为字幕句；技术词、数字、公式和专名不被随意改写。
- 润色失败时保留快速译文，并显示可诊断错误。

## 可选译文语音播报

**目标**：验证 final 字幕后可进入译文播报队列，并且暂停、停止可用。

**步骤**

1. 确认系统支持 Web Speech `speechSynthesis`。
2. 开启任意可生成 final 字幕的输入来源。
3. 打开“译文播报”。
4. 生成一条 final 翻译字幕，观察播报队列。

**通过标准**

- final 字幕加入播报队列。
- 播报状态在排队中、播报中、待播报之间切换。
- 暂停播报和停止播报可用。
- 环境不支持 Web Speech 时，字幕输出不受影响，并显示语音播报不可用。
