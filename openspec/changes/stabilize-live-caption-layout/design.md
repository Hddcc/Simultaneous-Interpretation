## Context

主页面通过同一个 `CaptionCue` 原位接收 ASR partial、ASR final、翻译草稿和 refinement 更新。当前 `.current-caption` 根据实际内容高度垂直居中，原文和译文段落没有高度边界，并允许内部滚动；因此任一文本换行都会改变字幕组总高度和纵向位置。最近上下文还会从零条动态增长到三条，继续改变活动字幕可用空间。

本次变更只处理主页面字幕几何稳定性。现有 cue 状态、翻译调度、历史投影和悬浮字幕已经具备独立职责，应继续复用。

## Goals / Non-Goals

**Goals:**

- 保持原文末行和译文首行之间的阅读锚点稳定。
- 让同一 cue 的长度变化和内容修订只更新文字，不重新定位整个字幕组。
- 消除主字幕正常使用时的滚动条、宽度变化和无界段落增长。
- 保持三档字号和常用窗口尺寸下的双语层级、可读性和完整历史数据。
- 通过聚焦场景验证连续修订期间的布局稳定性。

**Non-Goals:**

- 改变 ASR 分段、翻译触发阈值、refinement 调度或 cue 生命周期。
- 冻结实时文字直到 final，或降低 partial 字幕更新频率。
- 新增字幕行数、锚点位置或自动缩放的用户设置。
- 重做悬浮字幕窗口、历史存储结构或 Electron IPC。
- 在主字幕区域展示一条 cue 的无限长度全文。

## Decisions

### Decision 1: Use fixed source and translation slots

主字幕使用两个独立的固定高度槽位。原文槽位默认容纳两行并将内容靠近槽位底部，译文槽位默认容纳四行并从槽位顶部开始排版。两个槽位之间保留固定间距，形成稳定阅读锚点。

槽位高度使用相对于各自字号的 `em` 尺寸，使现有小、中、大字号偏好可以同步缩放。活动字幕容器保留整体居中，但其参与居中的总高度固定，因此文本从一行增长到多行时不会移动阅读锚点。

备选方案是把整个字幕组改为顶部对齐。该方案只能固定原文首行，原文换行仍会向下推动译文。独立槽位可以同时稳定原文末行和译文首行。

### Decision 2: Bound overflow with CSS line clamping

每个槽位隐藏溢出并使用固定行数截断；主字幕容器使用 `overflow: hidden`，不生成可见滚动条。完整 `CaptionCue` 文本保持不变，现有历史投影继续保存全文。

首版采用 CSS 槽位和行数限制，不引入 `ResizeObserver`、逐字符测量或连续动态字号。文本测量会增加状态和重排次数，动态字号也会在流式增长期间制造新的视觉变化。若真实样本证明四行译文仍频繁溢出，可以后续增加每个 cue 只切换一次的紧凑字号档位。

### Decision 3: Reserve a stable recent-context track

`caption-stage` 为最近上下文保留固定高度的网格行，组件在内容为空时仍渲染该占位。最多三条最近上下文继续单行省略显示。历史条目从零条增长到三条时只填充既有空间，不改变活动字幕区域高度。

备选方案是移除最近上下文。固定占位可以保留现有短期阅读上下文，并避免改变产品信息层级。

### Decision 4: Keep layout verification focused and observable

在现有歌词式字幕桌面场景中增加稳定性检查，覆盖短文本到多行文本、partial 到 final、refinement 修订、最近上下文数量变化、三档字号和窗口缩放。验收时记录原文锚点和译文锚点的 `getBoundingClientRect()`；在视口和字号不变的同一 cue 更新序列中，锚点偏移容差为一个 CSS 像素。

自动化测试继续覆盖场景定义和预期检查项，实际像素位置通过 Electron 窗口中的聚焦手动验证确认。引入完整浏览器视觉测试框架会扩大当前变更范围。

## Risks / Trade-offs

- [Risk] 超过行数上限的活动字幕会暂时隐藏尾部内容。 -> Mitigation: provider 继续按句生成 cue，四行译文覆盖常见长句，完整文本保留在历史中，并用真实长句样本验证上限。
- [Risk] 很矮的窗口或大字号可能压缩可用空间。 -> Mitigation: 使用现有响应式断点调整槽位和上下文尺寸，同时保持固定锚点、无重叠和无滚动条。
- [Risk] CSS 行截断在不同 Chromium 版本存在细微渲染差异。 -> Mitigation: 以项目固定 Electron/Chromium 运行时验证，并保留 `overflow: hidden` 作为确定性边界。
- [Risk] 最近上下文固定占位会在会话开始时留下空白。 -> Mitigation: 将占位限制为紧凑的三行上下文高度，换取整个会话期间稳定的字幕位置。

## Migration Plan

1. 调整主页面字幕标记，始终渲染最近上下文轨道，并为原文和译文增加槽位容器。
2. 增加固定槽位、行数限制和响应式边界样式，移除主字幕内部滚动。
3. 扩展歌词式桌面验证场景和测试，执行构建、现有测试与聚焦手动验证。
4. 使用真实连续语音复核锚点稳定性和超长字幕可读性。

回滚只需恢复主页面字幕标记和对应样式；数据模型、历史记录和 provider 链路不需要迁移。

## Open Questions

无。默认采用原文两行、译文四行以及三条固定高度最近上下文；真实样本验证结果可以在实现阶段微调响应式尺寸，不改变行为契约。
