## Why

悬浮字幕当前只能读、不能控，且读不全、还挡桌面：

1. 开始与暂停只存在于主客户端工具栏，用户看字幕时必须切回客户端才能控制翻译。
2. 悬浮字幕的源文与译文被限制为单行显示，长句永远只显示开头几个字；缩小字号只能在同一行里多塞几个字，无法解决截断。
3. 悬浮窗以不透明背景板渲染，遮挡下方的浏览器、会议和播放器内容，和桌面歌词类应用的观感差距明显。

此外，主窗口每次推送字幕都会把悬浮窗的字号、锁定和透明偏好覆盖回默认值，用户在悬浮窗里的调整无法保留。

## What Changes

- 在悬浮字幕控制条内提供开始与暂停翻译入口，命令经主进程转发到主窗口现有会话控制，不新增第二条采集链路。
- 解除悬浮字幕单行限制，让当前句按需换行完整显示，同时保持正常使用下无滚动条。
- 为悬浮字幕预留固定行数（上一句 1 行、源文 2 行、译文 3 行），使流式译文在预留空间内增长而不改变窗口高度；超出预留时窗口只涨不跌，等这句稳定后才收回，避免逐 token 抖动造成的闪烁。
- 悬浮字幕改为顶部对齐并渲染上一句淡显文本，让用户一眼分辨哪一句已经过去、哪一句正在翻译。
- 将悬浮窗改为透明窗口，默认不绘制背景板，改用文字描边与投影保证浅色和深色桌面下的可读性，并提供无背景、淡背景、深背景三档切换。
- 提供网易云音乐歌词式的鼠标穿透：点击锁图标开启穿透后字幕区域不再拦截点击，鼠标移入悬浮窗时仍会浮出解锁图标。
- 由于透明窗口不宜同时开启拖拽缩放，悬浮窗宽度改为控制条按钮分档调整，拖动移动位置的能力保持不变。
- 将悬浮窗显示偏好的所有权移到主进程，字幕内容更新不再覆盖用户在悬浮窗内选择的字号、背景档和锁定状态。
- 关闭主窗口与悬浮窗渲染进程的后台节流，确保用户只看悬浮字幕、主客户端被最小化或遮挡时翻译速度不下降。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `desktop-caption-experience`: 明确悬浮字幕内的会话控制、透明与鼠标穿透行为、宽度分档调整以及悬浮窗显示偏好的持久归属。
- `lyric-caption-playback`: 明确当前句在悬浮窗内完整显示与高度自适应的要求，替换原先依赖固定窗高的单行截断策略。

## Impact

- 受影响代码主要包括 `electron/main.ts`、新增的 `electron/floatingWindowLayout.ts` 与 `src/captions/floatingHeight.ts`、`electron/preload.ts`、`types/preload.d.ts`、`src/App.tsx`、`src/main.tsx` 和 `src/styles.css`。
- Electron preload 契约新增悬浮窗偏好、宽高调整、鼠标穿透和会话命令通道，`FloatingCaptionState` 增加 `running` 与 `backdrop` 字段。
- 新增工作全部位于悬浮窗渲染进程与主进程，不进入 ASR、翻译或调度热路径；高度自适应经过阈值与 requestAnimationFrame 合帧节流。
- 不新增第三方依赖，不改变现有语言选择、音频采集、provider 配置和翻译链路。
- 主客户端既有的解锁字幕与重置位置入口保持可用，作为平台不支持穿透时的兜底。
